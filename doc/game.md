# 3D Connect Four — ゲーム仕様書

クラシックな「コネクトフォー (重力あり 4 目並べ)」を 4×4×4 の立方体盤面に
拡張した 3D ゲーム。ブラウザ上で Three.js を用いて立体的に表示し、
オフライン (2 人 / vs AI) とオンライン対戦の両方をサポートする。

## 1. 基本ルール

### 1.1 盤面

- 4 (X) × 4 (Y) × 4 (Z) = 全 64 マスの立方体。
- 内部表現は `Player[][][]` で `board[x][y][z]`。
  - `Player = 1 | 2 | null` (`types/GameBoard.ts`)。
- Y 軸は **上下方向** (重力の反対向き)。X / Z は水平面。

### 1.2 着手と重力

- プレイヤーは盤面の **底面** (X-Z 平面) のマスをクリックして駒を投入する。
- 駒は重力に従い、その (x, z) 列の最も低い空マス (最小 y) に積まれる。
- 列が満杯 (`y` がすべて埋まっている) のとき、その (x, z) には投入不可。

### 1.3 勝利条件

- 同じプレイヤーの駒が **任意の直線方向に 4 つ連続** で並ぶと勝利。
- 直線方向は 13 種 (重複を排除した 26 方向):
  - 直交 3 軸: X / Y / Z
  - 軸を含む平面の対角線
  - 3D 空間の対角線 (立方体の頂点から頂点へ)
- すべて埋まり勝者がいない場合は引き分け。

### 1.4 手番

- プレイヤー 1 が先手 (`currentPlayer = 1` で初期化)。
- 着手のたびにプレイヤーがトグル (1 ↔ 2)。

## 2. ゲームモード

タイトル画面 (`components/title-page.tsx`) で以下から選択する。

| モード           | 概要                                                                       |
| ---------------- | -------------------------------------------------------------------------- |
| **2 プレイヤー** | 同一画面で 2 人対戦。手番に応じてマウス操作するだけ。                      |
| **vs AI**        | コンピュータ (プレイヤー 2) と対戦。難易度は 簡単 / 普通 / 難しい。        |
| **オンライン**   | サーバ経由で別端末のプレイヤーと対戦。ルーム作成 / 参加 / クイックマッチ。 |

## 3. AI の挙動 (`getAIMove`)

`app/page.tsx` のヒューリスティクス AI。Minimax ではなく評価関数ベース。

1. **勝ち手の検知**: 自分が勝てる手があれば必ず取る (全難易度共通)。
2. **相手の勝ち手のブロック**: 相手が次手で勝てる位置を塞ぐ。
   - 簡単のみ 30% の確率で見逃す。
3. **位置評価**:
   - 中央寄りのマスにボーナス (`evaluatePosition`)。
   - 自分のラインの伸び具合を評価 (`evaluateLines`、難しいモードのみ)。
   - 難しいモードは加えて相手の脅威 (`evaluateOpponentThreats`) を減算。
4. **ランダム要素**: 同点の手のばらけを出すため難易度別に乱数を加算。
   - 簡単: 0–50 / 普通: 0–20 / 難しい: 0–5
   - 簡単はさらに 50% の確率で完全ランダム着手にフォールバック。

| 難易度 | 期待される強さ                                                 |
| ------ | -------------------------------------------------------------- |
| 簡単   | 初心者向け。明らかな勝ち手は取るがブロックを忘れることがある。 |
| 普通   | バランス型。基本的なリーチ阻止と中央押さえを行う。             |
| 難しい | ライン評価と相手脅威評価まで考慮。先読み 1 手分相当。          |

> Minimax / αβ 探索は未実装。強くしたい場合は深さ 2〜3 の探索追加が候補。

## 4. リーチライン表示 (`findReachLines`)

- プレイヤーの駒が 3 つ + 重力的に到達可能な空マス 1 つで構成される
  「あと 1 手で 4 連」のラインを検出する。
- 既存ピースは小さな半透明球、勝利可能位置は大きな半透明球で表示し、
  接続線を細い円柱で結ぶ。プレイヤー色で発光し、`useFrame` でパルスする。
- 重力チェック: 空マスの真下に支えがあるか、もしくは y=0 のときのみリーチ扱い。

## 5. 3D 表示

`@react-three/fiber` の `<Canvas>` 内に以下を配置:

- **GridFrame**: 縦線/横線の格子 (設定で表示切替)。
- **GamePiece**: 駒。8 種の形状から選択可能。
  - 球体 / 立方体 / 円柱 / 円錐 / 八面体 / 十二面体 / トーラス / ダイヤモンド
  - 駒は `useFrame` でゆっくり Y 軸回転。
- **クリックメッシュ**: 盤面底面に 16 枚の半透明緑パネル。クリックで `onCellClick(x, z)`。
  AI 思考中は灰色化して操作不可を示す。
- カメラは `<OrbitControls>` で自由回転・ズーム可能。

## 6. カスタマイズ

ゲーム中の設定パネルから変更可能:

- **プレイヤー色**: 8 色プリセット (`COLOR_PRESETS`)。
- **駒の形状**: プレイヤーごとに 8 形状から選択。
- **グリッド表示**: 縦線 / 横線の表示切替。
- **背景**: タイトルでランダム選択 (`components/background/`)。
  - `connect4-title-background` / 幾何学 / ネオン / ミニマリスト

## 7. オンライン対戦フロー

```
[Player A]                    [Server]                        [Player B]
   │                             │                                │
   │ POST /api/game/create or quick-match                         │
   ├────────────────────────────▶│                                │
   │ ◀──── { roomId, playerId } ─┤                                │
   │                             │                                │
   │ GET /api/game/{roomId}/events (SSE)                          │
   ├────────────────────────────▶│                                │
   │                             │                                │
   │                             │  POST /api/game/join/{roomId}  │
   │                             │◀───────────────────────────────┤
   │                             │  または quick-match で合流     │
   │                             │                                │
   │ ◀── SSE: player-joined ─────┤── SSE: game-state ───────────▶│
   │                             │                                │
   │ (Host) POST .../start       │                                │
   ├────────────────────────────▶│                                │
   │ ◀── SSE: game-started (×3) ─┤── SSE: game-started (×3) ────▶│
   │                             │                                │
   │ POST .../move {x, z}        │                                │
   ├────────────────────────────▶│                                │
   │ ◀── SSE: game-state ────────┤── SSE: game-state ───────────▶│
```

### 主なエンドポイント

| メソッド + パス                 | 役割                               |
| ------------------------------- | ---------------------------------- |
| `POST /api/game/create`         | 新規ルーム作成 (作成者がホスト)    |
| `POST /api/game/join/[roomId]`  | 既存ルームへ参加                   |
| `POST /api/game/quick-match`    | 空きルームに自動参加、なければ作成 |
| `GET /api/game/[roomId]/events` | SSE で部屋状態 / イベントを受信    |
| `POST /api/game/[roomId]/start` | ホストがゲーム開始シグナル送信     |
| `POST /api/game/[roomId]/move`  | 駒を打つ ({playerId, x, z})        |

### 部屋の寿命

- 30 分間アクティビティが無いルームは自動削除 (`cleanupInactiveRooms`)。
- ホスト/ゲストが切断するとプレイヤーの `connected = false` が立つが、
  部屋自体はすぐ削除されない (再接続の余地を残す)。

## 8. 既知の制限事項

- **サーバ側の勝利判定が未実装**: `GameManager.checkWinner` は `return null`
  のみ。実質クライアント側の表示にしか反映されない。複数クライアント間で
  勝敗結果を厳密に保証したい場合は実装が必要。
- **インメモリ状態**: `lib/game-manager.ts` のシングルトンに保存しているため、
  サーバ再起動 / サーバレスのインスタンス分散で部屋が消える。
- **手の戻しなし**: 「待った」やリプレイ機能は未実装。
- **リーチライン**: 相手の hint は表示しない (`visibleReachPlayers` 参照)。
  - `vs-ai`: プレイヤー 1 (人間) のみ表示。
  - `online`: 自分側 (`onlinePlayerId` の slot) のみ表示。
  - `two-player` (パスアンドプレイ): 手番側のみ表示。
- **タイマー / 持ち時間**: なし。

## 9. 用語集

| 用語          | 定義                                                             |
| ------------- | ---------------------------------------------------------------- |
| 列 (column)   | (x, z) を固定したときの y=0..3 の縦 1 列。重力で積み上がる単位。 |
| ライン (line) | 4 連の候補となる 4 マスの直線。13 方向 × 各位置で複数存在。      |
| リーチ        | あと 1 マスで 4 連完成 (重力的に到達可能)。                      |
| ルーム        | オンライン対戦の対戦単位。6 桁英数 ID で識別。                   |
| ホスト        | ルーム作成者。ゲーム開始操作の権限を持つ。                       |
